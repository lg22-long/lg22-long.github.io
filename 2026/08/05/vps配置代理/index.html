🐱 VPS 使用 clash-for-linux 配置代理笔记

适用场景：在 Linux VPS 上通过 Clash 代理加速访问 GitHub、Google 等外网资源。

📌 背景与原理

国内 VPS 直连 GitHub 等海外服务通常速度极慢甚至超时。通过部署 Clash 代理客户端，将 VPS 的 git、curl、wget 等 TCP 流量通过代理节点转发，可显著提升下载速度。

核心原理：Clash 在本地 127.0.0.1:7890 开启 HTTP/SOCKS5 代理服务，通过设置环境变量或 Git 配置，让网络工具自动使用该代理。

❓ 常见问题排查

Q1：ping youtube.com 不通，但 curl 能通？

A：正常现象。ping 使用 ICMP 协议，Clash 默认仅代理 TCP/UDP，不处理 ICMP。只要 curl 返回 200，代理即生效。

Q2：curl 不加 -x 参数也能通？

A：因为安装脚本已将代理写入 /etc/profile.d/clash.sh，当前 SSH 会话自动加载了 http_proxy 环境变量。但该方式依赖 Shell 环境，使用 sudo 或后台任务时会失效，因此仍建议配置 git config --global 作为兜底。

Q3：切换节点后感觉速度没变化？

A：可运行 clashctl select 手动选择延迟较低的节点，或通过 Web 控制台 http://127.0.0.1:9090/ui 查看节点实时延迟。

Q4：sudo git clone 还是慢？

A：sudo 默认重置环境变量，不会继承 http_proxy。解决方案：已配置 git config --global 的情况下，sudo 也会读取该配置，因此不受影响。

🔒 安全提示

  • 订阅地址等同于你的代理凭证，勿公开分享。
  • Web 控制台默认监听 127.0.0.1:9090，如需外网访问，请设置 CLASH_SECRET 强密码并配置防火墙。
  • 开启 TUN 模式可能影响 SSH 连接，非必要不建议开启。
