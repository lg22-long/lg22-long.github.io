概述

Fastjson是阿里巴巴的开源JSON解析库，它可以解析 JSON 格式的字符串，支持将 Java Object 序列化为 JSON 字符串，也可以从 JSON 字符串反序列化到 Java Object。

FastJson提供了两个主要接口来实现对于Java Object的序列化和反序列化操作。

  • JSON.toJSONString
  • JSON.parseObject/JSON.parse

简单使用

对于Fastjson来讲，并不是所有的Java对象都能被转为JSON，只有Java Bean格式的对象才能Fastjson被转为JSON。

什么是java bean

一个合法的 JavaBean 必须严格遵循以下三条规则：

  • 提供公共无参构造函数：类必须包含一个 public 修饰的无参构造方法（如果不写任何构造方法，编译器会默认生成）。框架（如 Spring、Jackson、Fastjson）需要通过反射直接调用 Class.newInstance() 或 Constructor.newInstance() 动态创建该对象。
  • 属性私有并通过 Getter/Setter 暴露：
    • 类的成员变量必须使用 private 修饰，实现数据封装。
    • 每个私有属性都需要提供符合驼峰命名规范的公有读写方法：
      • 读方法：public Type getPropertyName()（若属性为 boolean 类型，通常是 isPropertyName()）。
      • 写方法：public void setPropertyName(Type value)。
  • 实现序列化接口（可选但标准规范强烈建议）：实现 java.io.Serializable 接口，以便对象能在网络中传输、保存到磁盘或在分布式会话（Session）间共享。

Fastjson中的@type

当我们在使用Fastjson序列化对象的时候，如果toJSONString()方法不添加额外的属性，那么就会将一个Java Bean转换成JSON字符串。

如果我们想把JSON字符串反序列化成Json Object，可以使用parse()方法。该方法默认将JSON字符串反序列化为一个JSONObject对象。

反序列化

下面我们来重点关注一下parse()方法是如何将一个JSON字符串反序列化为一个JSONObject对象的

parseObject()只是对于parse()做了封装，判断返回的对象是否为JSONObject实例并强转为JSONObject类。

下面我们来测试一下，首先不使用@type标识

由于没有指定对象所属的类，Fastjson只是默认将JSON反序列化为了JSONObject。

下面我们再来看看加上@type标识的情况，这里我们使用parse()方法反序列化

可以推测出在反序列化过程中，会parse()先调用@type标识的类的构造函数，然后再调用setter给对象赋值。

使用parse时Fastjson在JavaBeanlnfo.build 中规定,若属性无Setter,但存在无参公有Getter

且返回值继承自Collection、Map或特定原子类型,解析器会调用Getter获取已有容器后再行填充。

而parseObject()方法会同时调用setter和getter

可以看见parseObject()方法返回的是一个JSON Object对象，因为该方法实际上是调用parse()方法，然后调用toJSON()方法将返回值强转为JSON Object。

所以这里调用setter的实际上是parse()方法，调用getter的是toJSON()方法。

反序列化时为什么会调用 Getter？

业务设计初衷：很多类的集合属性“只有 Getter，没有 Setter”

如果我们不使用@type，而是在parseObject()中手动指定类
